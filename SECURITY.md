# Security Policy

Capital Parcel is a continuously deployed student research project. Only the current production version on the `main` branch is supported with security updates.

## Report a vulnerability privately

Do not open a public issue for an unpatched vulnerability, exposed credential, authentication bypass, Row Level Security gap, administrator-access problem, or other issue that could put data or users at risk.

Use [GitHub private vulnerability reporting](https://github.com/Parsa-Shakeri/mid-atlantic-cre-intelligence/security/advisories/new). If that option is unavailable, use the professional contact method listed on the live site's [About page](https://mid-atlantic-cre-intelligence.vercel.app/about) and share only enough information to arrange a private report.

Include:

- A concise description of the issue and its likely impact
- The affected URL, route, component, or database policy
- Reproduction steps using non-sensitive test data
- A minimal proof of concept, when safe
- Suggested remediation, if known

Do not include real credentials, private personal information, confidential records, proprietary data, or unnecessary production data.

The project aims to acknowledge a complete report within seven days and provide a triage update within fourteen days. As an independent student project, response times are targets rather than guaranteed service levels.

## Scope and safe testing

Testing must not degrade service, access another person's account, change production records, send unsolicited traffic, or use automated high-volume scanning. Social engineering, denial-of-service testing, physical attacks, and vulnerabilities limited to third-party services are outside scope.

Please allow time for a fix before public disclosure. No bug bounty or monetary reward is offered.

Published-data disagreements, missing sources, and calculation questions are not security vulnerabilities. Submit those through the repository's **Data correction or source update** issue form.
